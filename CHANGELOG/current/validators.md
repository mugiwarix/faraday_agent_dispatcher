[ADD] Approved validation profiles now live in official executor manifests (`validation_profiles`) and are exposed by `faraday_agent_dispatcher.utils.executor_profiles`. Both Nmap and testssl profiles run bundled official Python executors; scanner command and evidence logic live in those scripts, with no parallel scanner package. Profile IDs, exact aliases, limits and plan arguments remain stable, except renegotiation MiTM no longer matches CVE-2011-1473 / client-renegotiation DoS evidence.

[SEC] Approved testssl mode requires trusted image `TESTSSL_PATH` pointing to an absolute regular executable (pinned testssl.sh 3.2.4). Commands are preflighted before scans, bind one literal IPv4/TCP endpoint and allowlisted check IDs, disable DNS and phone-out, and ignore normal-mode custom flags, SNI, STARTTLS and OpenSSL overrides. Executor owns temporary evidence files and emits bounded Faraday `hosts` + `command` JSON with `validation_evidence`; evaluators also accept historical evidence envelopes. Missing, malformed, failed, duplicate or conflicting evidence is inconclusive; only direct positive evidence can imply true-positive status. Approved scanner streams/timeouts and testssl child file sizes are bounded; nonzero scanner exit cannot produce positive evidence. Runner still owns authorization, process-group cleanup and final stdout limits. Nmap retains existing reverse-DNS behavior.

[FIX] testssl vulnerabilities use parser-compatible `data` instead of `tool`/`output` fields. Normal scans retain their configuration interface; analysis-error severities and client-renegotiation DoS cannot produce pinned-severity MiTM findings.
