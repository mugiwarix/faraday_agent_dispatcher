[ADD] Added `faraday_agent_dispatcher.validators`, the package-owned home for validator profiles. Each profile binds one approved executor to a fixed target policy (single literal IPv4/TCP endpoint, no hostname or SNI), a closed set of evidence criteria, and the exact command that may run; the manifest is the only source of commands, flags, timeouts, and verdicts. Nmap evidence reuses the bundled official `nmap.py` executor and its `faraday_nmap` output contract, and testssl evidence follows the upstream `id`/`severity`/`finding`/`ip`/`port` record schema. Profiles, the pinned manifests (`nmap-tls-protocols.json`, `testssl-3.2.4-ssl-tls.json`), and the runner-facing execution hooks (`build_command`, `collect_evidence`, `runtime_environment`) ship with the distribution. Nothing in the package launches a process, resolves a hostname, reads a database, or imports a dispatching application, so a runner can reuse Faraday executor structure instead of duplicating it. The pinned scanner versions remain the images' responsibility.
